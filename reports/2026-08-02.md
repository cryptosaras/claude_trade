### Why this is a census, not a backtest

My first design was a `whale_absorb_hold` strategy file with a 50%-away stop, run
through the backtester against a `whale_absorb` control. **I am discarding that
design before running it, and recording why**, because the flaw is instructive:

- Every hold would run the full 8h, while the control exits at 1.5R in ~5h.
  With `max_positions_per_strategy: 3` and `max_positions_per_group: 2`, the hold
  variant would **decline entries the control accepted** — and the declines would
  not be random. They would fall on exactly the bursty absorption cascades this
  repo has documented (ORDI×2, TRB×5, JASMY×4). "Hold vs control" would partly be
  measuring *which trades each was allowed to take*, which is the slot confound
  already recorded in this repo's own notes.
- A 50% stop distance also drives `notional = risk/sl_dist` to ~123 USDT, a
  40× different sizing regime from the control.

**The census has neither problem.** It computes the forward 8h return from every
qualifying signal directly — no broker, no slots, no sizing, no leverage. That is
how the study itself measured, so it is a like-for-like replication rather than a
different experiment wearing the same name.

### What is measured

Rebuild the clause census (yesterday's throwaway tool; the "Note on method"
flagged it as worth rebuilding — this is the third session to need it). For every
closed 15m bar in the window, on every symbol, evaluate `whale_absorb`'s entry
conjunction **exactly as `should_enter` does** — `vol ≥ 2.5× avg20`,
`range ≤ 0.9 ATR`, `low within 0.3 ATR of the 12h low`, `6h return ≤ −1.5%`, and
the resulting 2.5-ATR stop distance inside [0.5%, 5%]. Then, from each signal,
measure three variants **on the identical signal set**:

| variant | exit rule |
|---|---|
| **RAW** | hold 32 bars (8h), no stop, no target — *the study's claim* |
| **STOP** | 2.5-ATR stop below the absorption low, else 8h |
| **STOP+TP** | 2.5-ATR stop, 1.5R target, else 8h — *the deployed `whale_absorb`* |

All three net of **0.16%** (0.10% fees round-trip at `fee_taker` 0.0005/side plus
0.06% slippage round-trip at 0.0003/side), which is the same 0.16% the study
states. **No fee or slippage number is touched** — these are read from
`config/settings.yaml`, not chosen.

Entry price is the **close of the signal bar**; the live engine enters at the next
tick, a uniform +15 min later. Stated, not hidden: the census is 15 minutes early
relative to live, on a 32-bar horizon.
